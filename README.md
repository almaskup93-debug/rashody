# Учёт расходов

Страница для личного учёта расходов. Работает без установки и внешних ресурсов. Данные сохраняются в localStorage текущего браузера; для проверок используйте вымышленные расходы.

## Что умеет
- [Добавлять трату](specs/001-dobavit-tratu.md): сумма, категория, дата, необязательный комментарий; последние добавленные записи сверху, итог текущего месяца.
- [Показывать итоги по категориям](specs/002-itogi-po-kategoriyam.md): Еда, Транспорт, Дом, Другое, Коммуналка, Подписки за текущий месяц, включая нулевые суммы. Новые категории добавлены по [спецификации 005](specs/005-pererashod-i-novye-kategorii.md).
- [Удалять отдельную трату](specs/003-udalit-tratu.md): список, общий итог и категории обновляются; удаление сохраняется после перезагрузки.
- [Задавать лимиты категорий](specs/004-byudzhet-po-kategoriyam.md) отдельно на каждый месяц, видеть потраченное и остаток. При равенстве лимиту — «Лимит достигнут», при превышении — красный «Перерасход» и отрицательный остаток. Выполнены шаги 1–3 бюджета; общий бюджет из шага 4 ещё не реализован.

## Как открыть и проверить
1. Скачайте проект в одну папку и откройте index.html двойным щелчком.
2. Добавьте за текущий месяц 5 000 и 2 500 в категорию Еда, 12 000 в Транспорт → итог 19 500 ₸, Еда 7 500 ₸, Транспорт 12 000 ₸, Дом и Другое по 0 ₸.
3. Нажмите F5 → траты и итог остаются.
4. Отправьте пустую сумму, abc, -100, 0, 12,50 → подсказка, список и итог не меняются.
5. На пустом хранилище добавьте 1 250 000 → показано 1 250 000 ₸.
6. Трата прошлого месяца видна в списке, но не меняет итог текущего месяца.
7. Проверьте ширину 375px: нет горизонтальной прокрутки, все поля и кнопки доступны.
8. Для примера из пункта 2 удалите Еда 2 500 → общий итог 17 000 ₸, Еда 5 000 ₸, Транспорт 12 000 ₸. Нажмите F5: удалённая запись не возвращается.
9. Добавьте две одинаковые траты по 5 000, удалите одну → другая остаётся. Удалите все записи → подпись «Пока нет трат» и все итоги по 0 ₸.
10. Попробуйте суммы 1 2 3 и 12 34 → подсказка, запись не создаётся. Сумма 1 250 000 принимается.
11. В разделе бюджета сохраните Еда 15 000. При расходах Еда 15 000 видно «Лимит достигнут» и остаток 0 ₸. Добавьте Еда 2 000 → «Перерасход» и −2 000 ₸ красным. Измените лимит на 20 000 → остаток 3 000 ₸, предупреждение исчезнет.
12. На отдельных вымышленных данных: Коммуналка — лимит 10 000, расход 12 000 → «Перерасход» и −2 000 ₸; Подписки — лимит 3 000, расход 3 000 → «Лимит достигнут». Нажмите F5 → значения и статусы остаются. Удаление траты сразу обновляет остаток.
13. У категории без лимита расход виден, остаток «—», предупреждения нет. Траты прошлого месяца не влияют на текущие лимиты. В новом месяце лимиты задаются заново.

Для проверки пустого состояния используйте отдельный профиль браузера либо удалите только вымышленные записи кнопками. Хранилище привязано к браузеру и адресу страницы: при переносе файла или открытии в другом браузере данные могут быть другими. Очистка данных браузера удаляет сохранённые траты. Если браузер запрещает localStorage для локальных файлов, страница сообщает об ошибке сохранения.

## Правила для агента

## Отчёт
Требования к первой функции созданы до реализации. Приложение использует только HTML, CSS и JavaScript, без внешних ресурсов.

Правило о неверной сумме оказалось недостаточно конкретным: первая реализация удаляла все пробелы и принимала 1 2 3 как 123. Расширенная автоматическая проверка обнаружила ошибку. Правило уточнено, проверка формата перенесена перед удалением пробелов. Повторная проверка отклоняет неверную группировку и принимает 1 250 000. Исправление и правило сохранены отдельным коммитом «Уточнить правило: проверять группировку тысяч».

Сразу сработали правила о спецификации до реализации, отсутствии библиотек и сетевых запросов, формате денег и обновлении README. В этом продолжении пользователь поручил выполнить готовые промпты ДЗ, включая команды «Делай по спецификации»: функции выполнялись последовательно, с требованиями перед кодом. Новые чаты автоматически не создавались; повторная проверка уточнённого правила выполнена в новом изолированном контексте выполнения JavaScript, а не в новом чате Codex.

Автоматически проверена логика в Node.js с имитацией DOM и localStorage: добавление, порядок записей, неверные суммы и группировка тысяч, 19 500 ₸, 1 250 000 ₸, исключение других месяцев, суммы категорий, удаление выбранной записи и повторная загрузка сохранённых данных. Проверены синтаксис JavaScript и отсутствие ошибок пробелов Git.

Остаётся проверить вручную в настоящем браузере все пункты «Готово, когда»: открытие двойным щелчком, настоящее F5, вид на 375px, размеры и доступность элементов. Управление браузером в рабочей среде было недоступно; дополнительная попытка проверки через Edge завершилась сообщением «DevTools remote debugging is disallowed by the system admin». Имитация DOM не подтверждает вёрстку и реальную работу localStorage браузера.

Проект отправляется в [репозиторий GitHub, ветка master](https://github.com/almaskup93-debug/rashody/tree/master). Для сдачи требуется проверить доступность ссылки без входа. Сдаётся только ссылка на публичный репозиторий.

После запроса о перерасходе добавлены расходы и остатки категорий, состояния «Лимит достигнут» и «Перерасход», категории «Коммуналка» и «Подписки». Автоматически проверены равенство лимиту, превышение на 2 000 ₸, изменение лимита, удаление, восстановление из хранилища, новые категории, прежние данные, другой месяц и ошибки хранилища. Проверки выполнены без создания файлов тестов, с имитацией DOM и localStorage; ручная проверка браузера и ширины 375px по-прежнему требуется.
